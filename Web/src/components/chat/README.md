# Shared Chat UI

`src/components/chat` is the stable import surface for chat UI shared by the web app and the VS Code webview. Import only the components a host needs, plus the shared skin when using page-level chat layout components:

```tsx
import '../../components/chat/styles.less';
import { ChatBox, ChatHeader, ChatPageLayout, ChatSidebarLayer } from '../../components/chat';
```

`ChatBox`, `MessageList`, `MessageBubble`, and `InputArea` are conversation primitives. `ProjectChanges` is the shared, source-only-in-Diff presentation for both providers, with changes/title supplied through props and no I/O. `ChatHeader`, `ChatSidebarLayer`, and `ChatPageLayout` compose the responsive page shell. Hosts own session state, navigation, and runtime-specific capabilities, and pass those through props; plugin-only behavior should not be embedded in the visual primitives.

`styles.less` is the shared skin entry. It currently reuses the existing chat page stylesheet so existing Web and VS Code layouts stay visually identical while styles are migrated into component-level files incrementally.

`ChatHeader` accepts `hasShareableMessages` and optional `onShare`. ChatPage derives eligibility from non-streaming user/assistant body text or body images, gated by session readiness/history loading. Attachment/project/tool-only cards do not qualify. The existing responsive SquareArrowOutUpRight control retains its styling, tooltip and accessible name; clicking starts real message selection. `ChatBox` / `MessageList` accept optional `shareSelection` and a toolbar supplied by the host. Stable message wrappers preserve ThinkingPanel/source disclosure state, and selecting does not trigger the conversation scroll revision.

VS Code omits both entries; ChatPage also gates share eligibility, selection, toolbar and preview so plugin mode cannot enter sharing. Desktop checkboxes overlay the existing left gutter. Narrow Web screens reserve a 44px left selection column inside the viewport, with both user and assistant bubbles to its right; ordinary mobile layout is unchanged. The native input remains keyboard accessible within a 44px target; the 23px visual uses Lucide Check (14px, 1.8px) and the exact Preview active background/border variables, with a 160ms fade and reduced-motion support. The toolbar floats 12px above the input dock and adds no flow height or message-tail padding. Ordinary and share modes keep the same 4px list bottom padding plus 4px container margin, so the last bubble ends 8px above the composer in either mode. ResizeObserver measures only the toolbar height for the scroll button anchor, retaining the button-to-toolbar gap (12px desktop / 10px phone); it never changes message spacing and disconnects/clears its variable on exit. `useChatShare` owns selection by message ID, export snapshots, cancellation and session cleanup. `shareContent` projects only original content/body images and readable citation names, preserving original message order regardless of click order. It never passes Thinking, project, tools, Preview, statistics or ChangeSet objects to `ShareImageTemplate`. The independent 750px template reuses the existing Jiangnan landscape, GFM Markdown and Gor branding. Assistant prose citations `[S1]` become readable source titles where available; unknown runtime IDs are removed. User text, code, inline code and explicit links remain unchanged; source cards are never rendered.

`exportShareImage` waits for images/fonts, embeds images locally and measures the entire independent template before generating one PNG with html-to-image. Width is 750 logical pixels and height grows with all selected content; the landscape, brand and footer each appear once. There is no pagination, fixed output height or aspect-ratio constraint. The preview scrolls the actual complete PNG and download saves the same blob. Rendering normally uses 2× resolution, with lower resolution retries subject to a conservative Canvas allocation budget (maximum side 16384 physical pixels / 16 million pixels, at least 1×). Content exceeding that single-image budget, mismatched Canvas dimensions or silent blank allocation fails explicitly; content is never cropped or split. Missing/CORS-blocked images, timeout or Canvas failure show an error. Closing preview retains selection; successful PNG download releases temporary URLs and exits share selection, while canceled/failed saves keep the preview and selection for retry. No LLM request, upload, public share link or automatic filesystem write is introduced.

Sharing is enabled only in Web/mobile and reuses `saveBlob`. The existing VS Code PNG save adapter and extension validation remain retained but are not connected to the plugin chat UI. Run `npm run test:share`, `npm run test:preview`, Web types/build and plugin tests/prepublish. `scripts/share-browser.fixture.html` is an explicit local acceptance fixture (sample content, not a user session); it exercises selection, real single-PNG generation for 1/5/20 messages, Markdown/images, failed images and extreme-size rejection.

Success/error toasts use the shared `FeedbackProvider`: center the icon and message together with a compact gap; keep the close control independently anchored at the right edge so it does not visually split the centered group.

`FileEditModeSelector` is shared presentation-only UI beside the composer upload button. It lists 审阅落笔 (BookOpenCheck) first, then 即刻落笔 (PencilLine; still the default), in an upward navy/purple glass panel, with outside-click and Escape dismissal. Optional `value` / `onChange` / `loading` props let hosts control the selected presentation; otherwise it defaults locally to instant. The host hook persists auto/review in one global database preference shared by every session and both hosts, then freezes execution mode at send. Its loading prop displays a spinner and disables repeat selection until the confirmed save finishes. Preference failures block sending instead of defaulting to auto; the selector itself performs no provider I/O. Run `npm run test:composer` for actual component switching, dismissal, focus and controlled-state regressions.

`ThinkingModeSelector` sits beside it inside the host's `.chat-composer-modes` wrapper and reuses the same trigger/popover/option styles. It offers, top to bottom, 酌思（auto） (`auto`, Scale, the default: the server picks 随思 or 深思 per message by rule and escalates to 深思 when it hits problems) / 随思 (`light`, Lightbulb, model deep thinking off) / 深思 (`deep`, Brain, deep thinking on), plus a "显示思考过程" switch below a divider. The "（auto）" tag is hidden on the trigger at ≤480px but always shown in the option list. Props: `value` / `onChange` / `loading` for the mode and `showThinking` / `onShowThinkingChange` for the switch; the component performs no I/O. The host persists the mode in the same global database preference shared by every session and both hosts, using `useThinkingMode` (built on the shared `useSessionPreference`, which also backs `useFileEditMode`); selecting a different model returns the shared thinking mode to the 酌思 default. For 酌思 turns, `ThinkingPanel` prints one muted line with what the turn actually used (e.g. 酌思 · 本轮随思（联网新闻）), restored from the trace's `thinkingMode`. Thinking visibility remains a separate global UI preference via `utils/thinkingVisibility`. Outside-click and Escape dismissal for both selectors live in `usePopoverDismiss`. Tests: `scripts/thinking-mode-ui.test.mjs` (part of `npm run test:composer`).

`ModelSelector` is the third chip in the same wrapper (Cpu icon + current model name). Props: `models` (from the server registry via `useChatModels`), `value`, `loading`, `onChange`; it renders nothing until models load, greys out and locks unavailable models, and performs no I/O. Model selection is temporary: the current page freezes the chosen model into each request, while server GET/reload/session change returns the registry default (DeepSeek V4.1 Flash). On phones (≤480px) all three chips hide their chevrons and the model chip shows only its icon. Tests: `scripts/model-selector-ui.test.mjs`.

## Shared Markdown code blocks

MarkdownCodeBlock overrides only ReactMarkdown pre nodes; inline code remains native. MessageBubble supplies actual streaming state, and ShareImageTemplate supplies share presentation (language header without copy controls). Dark+ token colors sit on the existing navy/purple skin. React escapes token content; there is no raw HTML injection.

codeHighlight/client starts one Worker on demand and coalesces identical language/source tasks in a bounded LRU (32 keys / 500,000 source-key characters). Web uses a module Worker; runtime loads only the requested grammar and Dark+ theme using Shiki core and its JavaScript regex engine. Supported declarations include TypeScript, JavaScript, TSX, JSX, Python, HTML, CSS, JSON, SQL, Bash and Vue, with common aliases; unknown declarations remain plain. A block beyond 100,000 characters or 2,500 lines keeps its complete source without highlighting. Worker errors/timeouts (15 seconds) safely fall back and allow later retries.

Streaming displays current raw source immediately and debounces coloring by 250ms; settled content highlights immediately. Cleanup prevents old results replacing current content. Chat code scrolls horizontally; share code wraps using the same token colors to preserve every character. exportShareImage waits for the asynchronous highlight/plain status to be committed before measuring or rendering the PNG. Copy uses the browser clipboard, shows a short success/failure state, and cleans up its timer on unmount.

The VS Code entry injects VscodeCodeHighlightWorker before mounting React. It lazily loads an inline Blob Worker containing the core, JavaScript engine and Dark+ in one file, without worker-side import()/importScripts. loadLanguage supplies main-thread lazy grammar chunks; each requested grammar is structured-cloned to the Worker once. Tokenization stays off the UI thread and existing CSP remains unchanged. Plugin chat and Diff use this transport; Web Preview and sharing remain excluded. Run npm run test:code, test:diff, test:share, test:preview, Web types/build, plugin tests and prepublish. The local fixtures exercise examples only; they do not run a model or represent a real Extension Host.

Diff and Preview now also reuse the highlight Worker after the user explicitly expanded the scope. CodeDiff supplies react-diff-view tokens/renderToken for actual before/after source fragments, keyed to their original line numbers. Available contiguous lines are colored together; unavailable gaps start a separate grammar context rather than fetching or inventing source. View mode, folds, raw diff, backgrounds and undo remain owned by existing components.

PreviewSourceViewer retains its actual Textarea (there is no Monaco in this implementation). A noninteractive aria-hidden pre supplies color only, with matching 11px Consolas/Courier metrics, 16px padding and tab size 2. It debounces edits by 250ms, ignores old path/source results, and syncs both scroll axes with the original editor and gutter. The native input remains the only editable/copyable source; the overlay's final zero-width character only preserves trailing-line height. Unknown languages and failed highlighting retain plain editable source.

## Toolchain (施行) cards

`ToolchainRunCard` is presentation-only: it receives a `ToolchainRunView` plus approve / skip / stop-round / abort / open-URL / shown callbacks and performs no extension, filesystem or network I/O. Background dev servers render as a 常驻施行 row with their local URL (opened by the extension after it re-validates a localhost address) and 止令; stopped ones show 已收令. `MessageBubble` renders cards only when a `ToolchainRunsContext` value is provided; ChatPage provides it in VS Code mode only (via `vscode/toolchainRuns.ts`), so Web never shows them. Status words map in `toolchainRun.ts` (待施行、正施行、已施行、未施行、见疏漏 / 未施成、内容有异、逾时未施、逾时而止、中道而止、此令未开、不可施行、未得信任、常驻施行、已收令); stored statuses are unchanged. The pending card defaults focus to 搁置 and Escape skips. It also shows why it asks (review not allowlisted / deletion / outside the project / suspected risk), risk warnings with their evidence (high-risk cards keep 施行 locked until 「我已看过以上风险，仍要施行」 is checked), detail lines such as the commit file list, an editable commit message, 「本轮内此命令不再询问」 when the extension allows it, and 「落笔并施行」 when unapplied review candidates exist. Collapsed rows keep the 疑似风险 / 高度可疑 tag. The store validates every field from the extension and only posts approve / approve_round / apply_and_run / skip / stop answers. Run `npm run test:toolchain`; the test loads React after the jsdom globals so input events reach React, and unmounts leftover cards after each test.

## Shared thinking presentation

`ThinkingPanel` receives `ThinkingTrace` through props and performs no host/provider I/O. The model adapter emits start/delta/end plus presentation-only thinking_update events; existing Agent phases and real tool start/end/file receipts provide accurate Chinese action titles and concise task summaries without another model request. Real tools outrank Agent phases, which outrank conservative model intentions/provider summaries. Unknown titles show 思考中, missing summaries occupy no space, and raw internal reasoning is not displayed. Plans and pending edits never claim completed execution.

The server projection associates actual tool events with the latest model round until the next start, clears old associations at that boundary, and persists title/summary/source/steps alongside existing reasoning. Late old-round updates and unmatched results cannot rewrite previous rounds. Single thinking_end is only a model boundary; Agent done/error/cancel determines terminal status. The latest round starts open, predecessors group behind 此前思考 · N 条, and deltas preserve user disclosure. Terminal runs collapse to one BookOpenCheck card 思考已完成 / 共 N 轮思考 (or accurate failure/cancellation/interruption text); opening history leaves each round's earlier observations closed. Refresh starts closed.

CSS Grid animates height and opacity for 250ms ease-out, rotates arrows, and fades first summaries in for 180ms. Closing nodes remain for 260ms and are immediately inert/aria-hidden. Reduced-motion disables animation/transitions. Thinking-only updates do not trigger MessageList scrolling. Each round header contains only its title. The expanded summary area shows the current task summary first, then earlier real observations without duplicating that summary; collapsed rounds hide all descriptions. Missing summaries have no placeholder. The separate tool-status label is hidden only when the panel already projects that tool. Shared Web, VS Code Webview and mobile presentation keeps the Gor brand and glass skin, without affecting tool callbacks, ChangeSet, Diff, undo or file modes. Run npm run test:thinking and root acceptance commands for both hosts.

Task icons are centralized in src/utils/thinkingIcons.ts: real tool names take priority over confirmed phase/task titles, with PencilLine for generic thinking/answer preparation and as the fallback. Round icons use 18px/1.7px soft purple; completed runs use BookOpenCheck at 20px/1.7px in #C5B3FF, while failed/cancelled/interrupted runs keep Brain. Keys follow icon/title identity, so only meaningful changes fade in for 180ms and summary updates do not restart the transition. Planning titles use ListTodo before editing keywords. No extra model request or animation dependency is introduced.

## Shared Diff presentation

`ProjectChanges` delegates each raw diff to `CodeDiff` using `react-diff-view`. Both hosts default to Unified (including mobile), with top-right Unified / Split controls, insertion/deletion counts, themed line colors and wrapping code. Web and VS Code use the same dark context-row canvas from the shared Diff stylesheet; insertion rows remain deep green and deletion rows muted red, while line numbers and +/- markers continue to reflect the actual Diff. Split displays before/after columns, including the empty side of created/deleted files. Gutters align numbers left with padding and a separate marker slot. `diffPresentation.ts` projects raw hunks without modifying the message data: each change keeps up to 3 available context lines; unchanged runs longer than 6 fold their middle, while nearby changes share context. Click `··· 省略 N 行` to expand locally available lines and collapse them again. Adjacent source hunks merge when both old/new line ranges meet. Gaps absent from the supplied diff show an explicit unavailable label, never fabricated source or an inoperative expansion button. Incomplete/unparseable diffs fall back verbatim; parsed views have no raw-Diff disclosure. The original payload remains unchanged. No current-source lookup or provider I/O is performed.

`ProjectChanges` renders the scheme-C deep-blue summary: “本次变更 · N 个文件”, status counts, two pill actions and compact rounded file rows. Each row contains a right/down chevron (180ms rotation), a muted extension badge, basename/status and a separate undo target. Arrow, badge and information activate the native disclosure; undo stops both propagation and disclosure activation. Files start closed and multiple files can open independently. Small screens stack name/status as needed, retaining fixed action space and wrapping long names. The optional `displayStatus` prop remains presentation-only for component fixtures. Live messages receive their ChangeSet ID from the `change_set` SSE event; sealed journals persist an exact `messageId` association and history returns compact `project_change_sets` references (no source snapshots). The host restores a unique validated reference and injects the existing Web or VS Code Project Change client. Legacy messages without an association, ambiguous multiple journals or wrong-session references never guess an ID. The component enables undo only for sealed `applied` records, serializes requests and refreshes state after success/partial failure. Batch counts include only applied files. Failures use the shared notification callback; an in-flight Preview edit preserved by the adapter is not falsely reported as fully synchronized. Receive calls the injected applyFile/applyChangeSet only for sealed pending records, shares the request lock and refreshes authoritative state after confirmation. Existing Chinese wording and visuals are unchanged. Reverted rows show only the completion icon. There is no footer note; original paths remain in tooltips and Diff, and line counts remain accessible.

The existing one-per-message Unified / Split toolbar appears alongside the group title only while a Diff is expanded, keeping the collapsed summary faithful to the reference. It passes the controlled mode to every `CodeDiff`. Collapsing a file does not reset the group mode; separate message groups remain independent. Raw revisions reset only that file's context expansion. `ProjectChanges.less` scopes summary styles without changing Diff typography or the surrounding chat layout. Three-state mock data exists in component tests only, not in user messages.

Run `npm run test:diff` from `Web` (projection, real-component expand/collapse and multi-file group controls), plus the Web and extension acceptance commands in root `project.md`.

`UndoConfirmModal` is shared, controlled UI with single/batch props and no provider access. Single shows the full receipt path; batch shows only the current applied count. Opening, cancellation, close, Escape and backdrop dismissal do not execute undo. Confirmation invokes the existing callback; the caller's in-flight lock and disabled modal controls prevent repeats. API responses and refreshed statuses remain authoritative. The scoped navy/purple glass style does not alter chat or Diff styling; no footer hints or file lists are added.

The close target stays above the decorative visual layer; decorations use `pointer-events: none` so they cannot intercept part of the close button on either host.

Narrow Web and VS Code Webview (below the existing 1024px desktop breakpoint) are Unified-only and omit the mode toolbar. `MessageBubble` supplies the responsive `allowSplit` capability; `ProjectChanges` never detects the host or reads viewport state. Entering narrow layout overrides any selected Split mode without changing raw data or expansion state; wide layouts retain the group switch.
